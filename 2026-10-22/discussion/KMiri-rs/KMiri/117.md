## Body

* https://github.com/rust-lang/unsafe-code-guidelines/issues/156

**一、Issue #156 到底在讨论什么**
- 议题：`#[repr(C)] union` 的 padding（包括内部/尾部 padding）在按值传参、返回、拷贝时，是否必须按位保留。
- 触发背景：不同编译器/ABI 对同一 union 的按值传递 lowering 可能不同，导致 padding 位不一致。
- 核心争论：`repr(C)` union 能不能当成“完整 bit bag（每一位都可依赖）”。

**状态与走向**
- `rust-lang/unsafe-code-guidelines#156` 创建于 **2019-07-03**，关闭于 **2023-08-02**。
- 关闭说明：转由 `#438` 继续处理
  - https://github.com/rust-lang/unsafe-code-guidelines/issues/438
- 方向：采用类似“chunked”模型表达 union 表示，区分“会保留的字节块”和“可丢失的 gap/padding”。

---

**二、最终可执行结论（工程视角）**
1. `repr(C)` 主要保证布局规则，不保证“所有 bit 在 ABI 边界都保真”。
2. union/aggregate 的 padding 在按值 ABI 中通常不可依赖，可能被丢弃或改写。
3. 因此不能把 `repr(C)` union 当作稳定“字节袋”来存隐含数据、做哈希、memcmp、持久化比较。

一句话版：
`repr(C)` 解决“怎么摆（layout）”，不承诺“每一位怎么传且必保真（ABI value transport）”。

---

**三、你前面那个判断，修正版**
你说“字段是 tuple，等价于字段本身有非 C ABI 问题”，这个判断是对的，但不完整：

- 问题 A：字段类型本身可能不是 FFI-safe（如 tuple）。
- 问题 B：即便字段类型 FFI-safe，padding 仍可能在 ABI 按值传递中不保留。
Issue #156 的主轴是 **B**，不是只讨论 A。

---

**四、示例完善**

### 示例 1：讨论语义用（原 issue 风格）
```rust
#[repr(C)]
union U {
    x: (u8, u32),
}
```
说明：
- 这是“可写”的 Rust 构造，但 `(u8, u32)` 不是推荐 FFI 字段类型。
- 用它讨论 padding 语义可以，但不适合作为“稳定跨语言接口模板”。

### 示例 2：更干净的 FFI-safe 讨论版
```rust
#[repr(C)]
struct S {
    a: u8,
    b: u32,
}

#[repr(C)]
union U {
    s: S,
    raw: u64,
}
```

常见布局（小端、常见 ABI 下）可直观理解为：
- `S`: `[a][pad][pad][pad][b0][b1][b2][b3]`，`size=8, align=4`
- `U`: `size=8, align=8`（因 `u64` 成员，具体以平台 ABI 为准）

关键点：
- `S` 的 3 字节 padding 不是稳定 payload。
- `U` 按值跨 ABI 边界后，`s.a`/`s.b` 语义可正确，但 `raw` 的某些比特可能与调用前不同（尤其涉及 padding 映射的部分）。

---

**五、为什么“默认保留 padding”不是简单答案**
你提出“默认保留最安全，提供属性给想优化的人”很合理，但这里有现实约束：

1. 某些 ABI lowering 下并不存在完整承载 padding 的通道，不是“愿不愿意优化”问题。
2. `extern "C"` 要兼容 C 生态，而 C 通常不承诺 padding 保真。
3. 问题发生在调用约定层面，不是单个字段属性就能局部解决。
4. 若引入“必须保留 padding”语义，会牵涉类型兼容、链接、跨平台降级策略等大设计问题。

---

**六、落地建议（避免踩坑）**
1. 不要在 padding 塞业务信息/标签/校验位。
2. 不要对含 padding 的 FFI 对象做 `memcmp` 等价判断或直接字节哈希。
3. 需要位级保真时：
- 用显式字节表示（如 `[u8; N]`）；
- 或改为指针/切片传输明确字节序列，而非按值传 union/aggregate；
- 在 Rust 内再做解析映射。
