# 解释 run_provenance_gc

## Body

`run_provenance_gc` 是 Miri 里的“指针 provenance 元数据 GC”，不是普通意义上的堆内存回收。

核心实现在 [src/provenance_gc.rs#L265](https://github.com/KMiri-rs/miri/blob/be40e95a94f7b8b4218ef2ee6272ac7b227eadf4/src/provenance_gc.rs#L265)，流程分三步：

1. 扫描整个解释器状态，收集“仍可达”的 `AllocId` 和 `BorTag`。
入口是 `this.visit_provenance(...)`，会遍历分配内容和 machine 状态里的各种结构（线程、TLS、FD、borrow tracker、extern statics 等）。
见 [src/provenance_gc.rs#L268](https://github.com/KMiri-rs/miri/blob/be40e95a94f7b8b4218ef2ee6272ac7b227eadf4/src/provenance_gc.rs#L268)、[src/provenance_gc.rs#L211](https://github.com/KMiri-rs/miri/blob/be40e95a94f7b8b4218ef2ee6272ac7b227eadf4/src/provenance_gc.rs#L211)、[src/machine.rs#L1120](https://github.com/KMiri-rs/miri/blob/be40e95a94f7b8b4218ef2ee6272ac7b227eadf4/src/machine.rs#L1120)

2. 用收集到的 live tags 清理借用跟踪器里的不可达 tag。
见 [src/provenance_gc.rs#L240](https://github.com/KMiri-rs/miri/blob/be40e95a94f7b8b4218ef2ee6272ac7b227eadf4/src/provenance_gc.rs#L240)。
Tree Borrows / Stacked Borrows 都有对应 `remove_unreachable_tags`，并且会显式保留 exposed/root 相关 tag，避免误删。
见 [src/borrow_tracker/tree_borrows/tree.rs#L1200](https://github.com/KMiri-rs/miri/blob/be40e95a94f7b8b4218ef2ee6272ac7b227eadf4/src/borrow_tracker/tree_borrows/tree.rs#L1200)、[src/borrow_tracker/stacked_borrows/mod.rs#L452](https://github.com/KMiri-rs/miri/blob/be40e95a94f7b8b4218ef2ee6272ac7b227eadf4/src/borrow_tracker/stacked_borrows/mod.rs#L452)

3. 用 live allocs 清理不可达分配 ID 的附加状态。
会清理 `allocation_spans`、`symbolic_alignment`、`alloc_addresses`、borrow tracker 里的 alloc 映射，以及 core interpreter 状态。
见 [src/provenance_gc.rs#L251](https://github.com/KMiri-rs/miri/blob/be40e95a94f7b8b4218ef2ee6272ac7b227eadf4/src/provenance_gc.rs#L251)、[src/alloc_addresses/mod.rs#L149](https://github.com/KMiri-rs/miri/blob/be40e95a94f7b8b4218ef2ee6272ac7b227eadf4/src/alloc_addresses/mod.rs#L149)

触发方式有两种：

1. 自动触发：在执行 terminator 前按 `gc_interval` 周期运行。
见 [src/machine.rs#L2042](https://github.com/KMiri-rs/miri/blob/be40e95a94f7b8b4218ef2ee6272ac7b227eadf4/src/machine.rs#L2042)

2. 手动触发：通过外部函数 `miri_run_provenance_gc`。
shim 入口见 [src/shims/foreign_items.rs#L362](https://github.com/KMiri-rs/miri/blob/be40e95a94f7b8b4218ef2ee6272ac7b227eadf4/src/shims/foreign_items.rs#L362)，测试封装见 [tests/utils/mod.rs#L15](https://github.com/KMiri-rs/miri/blob/be40e95a94f7b8b4218ef2ee6272ac7b227eadf4/tests/utils/mod.rs#L15)。
非 Miri 环境下它是空实现（no-op），见 [tests/utils/miri_extern.rs#L205](https://github.com/KMiri-rs/miri/blob/be40e95a94f7b8b4218ef2ee6272ac7b227eadf4/tests/utils/miri_extern.rs#L205)

一句话总结：它是在“压缩并清理 Miri 的 provenance/borrow-tracking 元数据图”，防止长期执行时元数据膨胀，同时保证仍可能被访问到的 tag/alloc 信息不被误删。
