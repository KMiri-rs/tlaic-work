## Body

在 Rust 1.84.0 中，用于处理指针来源（Provenance）的一系列 API 已经正式稳定。这些 API 旨在用更显式、对编译器和静态分析（如 Miri）更友好的方式，来逐步替代传统的整数指针互转（`as` 强转）。

这些 API 可以分为三大核心模型：
1. **严格来源模型（Strict Provenance）**：通过保留原指针的来源，不进行隐式暴露来修改地址。
2. **暴露来源模型（Exposed Provenance）**：传统的“指针 $\rightarrow$ 整数 $\rightarrow$ 指针”生命周期模型，允许来源在全局被“暴露”和“重新拾起”。
3. **无来源模型（No Provenance）**：创建完全没有分配关联（无权限）的指针。

---

### Rust 1.84.0 指针 Provenance 相关的 API 汇总表

以下是将 **API/函数名** 与 **调用主体** 合并为一列（整合为直观的代码调用语法形式）后的整理表格。这样可以更清晰地看出哪些是属于指针实例的“方法”，哪些是属于 `core::ptr` 模块的“关联函数”：

### Rust 1.84.0 指针 Provenance API 整合汇总表

| 函数 | 输入类型 | 输出类型 | 传统 / 等价写法 | 核心语义与作用 |
| :--- | :--- | :--- | :--- | :--- |
| **`ptr.addr()`** | `ptr: *const T` 或 `*mut T` | `usize` | *`transmute(ptr)`<br>(纯读取，无暴露)* | **只获取地址**。仅读取指针的数值地址，**不会**把该指针的来源（Provenance）标记为已暴露。 |
| **`ptr.expose_provenance()`** | `ptr: *const T` 或 `*mut T` | `usize` | `ptr as usize`<br>*(带暴露副作用)* | **获取地址并暴露来源**。获取数值地址，同时向编译器声明**暴露**其 Provenance，以便后续通过地址重建指针。 |
| **`ptr.with_addr(addr)`** | `ptr: *const T` 或 `*mut T`<br>`addr: usize` | `*const T` 或 `*mut T`<br>*(与 `ptr` 同类型)* | `(ptr as *const u8)`<br>`.wrapping_offset(...)` | **修改地址，锁死来源**。使用 `addr` 生成新指针，但新指针**直接继承并锁死** `ptr` 的 Provenance。（最推荐的地址修改方案）。 |
| **`ptr.map_addr(f)`** | `ptr: *const T` 或 `*mut T`<br>`f: impl FnOnce(usize) -> usize` | `*const T` 或 `*mut T`<br>*(与 `ptr` 同类型)* | `ptr.with_addr(f(ptr.addr()))` | **映射修改地址**。对当前指针的地址应用闭包运算，保留原 Provenance。常用于指针对齐或标记指针（Tagged Pointer）计算。 |
| **`with_exposed_provenance(addr)`** | `addr: usize` | `*const T` | `addr as *const T` | **根据已暴露来源重建常量指针**。从全局“已暴露的 Provenance 池”中猜测并重构回一个有效的只读指针。 |
| **`with_exposed_provenance_mut(addr)`** | `addr: usize` | `*mut T` | `addr as *mut T` | **根据已暴露来源重建可变指针**。同上，但重构回一个可变（写入）指针。 |
| **`without_provenance(addr)`** | `addr: usize` | `*const T` | `core::ptr::null()`<br>`.with_addr(addr)` | **创建无来源的常量指针**。强制将地址转为指针，但它不携带任何 Provenance。对其解引用会直接引发未定义行为（UB）。 |
| **`without_provenance_mut(addr)`** | `addr: usize` | `*mut T` | `core::ptr::null_mut()`<br>`.with_addr(addr)` | **创建无来源的可变指针**。同上，但返回可变（写入）指针。 |

*(注：除了以上方法外，`core::ptr::NonNull<T>` 也拥有相对应的 `with_exposed_provenance` 等同名方法)*。

---

### 关键差异与经典写法的“陷阱”

在使用这些 API 代替经典 `as` 强转时，有以下几点需要注意：

#### 1. `as usize` 与 `.addr()` / `.expose_provenance()` 的本质区别
* 传统的 `ptr as usize` 实际上等价于较慢、较不安全的 **`.expose_provenance()`**。它不仅读取了地址，还会产生全局副作用（把当前指针的访问权限标记为“所有人均可猜测并拾起”），限制了编译器的优化空间。
* 只要你**不需要**在以后把这个 `usize` 强转回指针（例如你只是想打印地址、做哈希、或者比对地址大小），请一律使用 **`.addr()`**。

#### 2. `as *const T` 与 `with_exposed_provenance`
* 传统的 `addr as *const T` 并非安全的指针重建。它等价于 `with_exposed_provenance(addr)`，要求在此之前必须有对应的指针调用过 `expose_provenance()`（或 `as usize`）。
* 如果 `addr` 是来自于一个不属于 Rust 抽象机器控制的硬件地址（如 Bare-metal 嵌入式开发中的 MMIO 寄存器地址），Rust 的内存模型仍默认允许使用 `with_exposed_provenance` 访问，因为硬件内存空间被默认为“已暴露”。

#### 3. 什么是 `without_provenance`？
* 如果你需要一个绝对干净的、代表“非内存对象”的临时指针（例如，仅仅用作哨兵值、对齐占位符或 FFI 中的某种数值标记），应当使用 `without_provenance(addr)`。
* 它与 `as *const T` 的区别在于：它**彻底斩断**了与任何已有变量或内存块的联系。对其解引用会直接引发未定义行为（UB），但它能提供极其安全的生命周期和权限边界隔离。
