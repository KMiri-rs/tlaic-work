# TockOS 的整体架构

- **Updated**: 2026-08-02T12:48:04Z

## Body

可以把 TockOS 看成“**板级装配的微内核 + capsule 服务层 + 进程隔离运行时**”。
下面按你关心的维度做一版架构图谱（都对应源码入口）。

**1. 内核与用户态边界**
1. 用户态通过固定 syscall ABI 进入内核，syscall 类别在 [`syscall`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/syscall.rs#L80-L96) 定义（`yield/subscribe/command/allow/memop/exit`）。
2. 真正的“上下文切换边界”由架构层 trait [`UserspaceKernelBoundary`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/syscall.rs#L473-L590) 抽象，芯片架构实现具体寄存器/栈帧细节。
3. 进程运行前后内核会切 MPU 保护，核心路径见 [`do_process`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/kernel.rs#L539-L556)。

**2. 内核服务形态（capsule / driver）**
1. 板子通过 [`KernelResources`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/platform/platform.rs#L20-L75) 把调度器、driver 路由、fault policy 等“策略对象”注入内核。
2. syscall 路由由 [`SyscallDriverLookup`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/platform/platform.rs#L77-L116) 完成，典型实现可看 [`nucleo_f446re with_driver`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/boards/nucleo_f446re/src/main.rs#L85-L103)。
3. capsule 通过 trait [`SyscallDriver`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/syscall_driver.rs#L262-L317) 提供 `command` 等行为；`subscribe/allow` 由 core kernel 统一处理。

**3. IPC 机制**
1. IPC 是一个“特殊 syscall driver”，定义在 [`ipc`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/ipc.rs#L5-L20)，driver number 是 `0x10000`。
2. 进程间通知通过入队 `Task::IPC`，触发 upcall，关键逻辑在 [`IPC::command`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/ipc.rs#L112-L220)。
3. IPC 共享内存通过 allow buffer + 内核校验/映射完成，调度 upcall 路径见 [`schedule_upcall`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/ipc.rs#L66-L109)。

**4. 进程管理**
1. 进程从 Flash 的 TBF 连续解析并装载，入口在 [`load_processes`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/process_loading.rs#L120-L162)。
2. 装载器按 `app_flash + app_memory` 建立 `ProcessStandard`，说明见 [`load_processes_from_flash`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/process_loading.rs#L164-L220)。
3. 进程状态机在 [`State`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/process.rs#L946-L997) 定义（`Running/Yielded/YieldedFor/Faulted/Terminated`）。
4. Fault 行为由策略 trait [`ProcessFaultPolicy`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/process_policies.rs#L18-L26) 决定（panic/restart/stop）。

**5. 内存管理**
1. 板级 linker 把 app flash / app ram 区域导出成 `_sapps/_eapps/_sappmem/_eappmem`，见 [`tock_kernel_layout`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/boards/build_scripts/tock_kernel_layout.ld#L293-L367)。
2. board `main` 将这两段切片传给装载器，见 [`nrf52840dk main`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/boards/nordic/nrf52840dk/src/main.rs#L96-L124)。
3. 单进程 RAM 内部是“app 区 + kernel 代表该进程的元数据区（grant/upcall/PCB）”，布局注释见 [`ProcessStandard memory layout`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/process_standard.rs#L446-L500)。
4. app 可通过 `memop brk/sbrk` 调整 break，见 [`memop`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/memop.rs#L16-L58)。

**6. 调度与执行流**
1. 内核主循环在 [`kernel_loop`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/kernel.rs#L413-L430)。
2. 单次循环三步是：做内核工作、挑进程运行、可睡眠；在 [`kernel_loop_operation`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/kernel.rs#L333-L410) 注释写得很清楚。
3. 调度器接口在 [`Scheduler`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/scheduler.rs#L14-L97)，支持 cooperative 或 timeslice preemptive。
4. 板子可选不同调度器实现，例如 [`round-robin`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/boards/nucleo_f446re/src/main.rs#L59) 与 [`cooperative`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/boards/qemu_rv64_virt/src/lib.rs#L46-L49)。

**7. 一条完整路径（从启动到运行）**
1. board 组装 capsule/scheduler/ipc，如 [`IPC::new + scheduler`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/boards/nucleo_f446re/src/main.rs#L533-L555)。
2. `load_processes()` 装载 app，如 [`board load`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/boards/nucleo_f446re/src/main.rs#L576-L593)。
3. 进入 [`kernel_loop`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/boards/nucleo_f446re/src/main.rs#L603-L610)。
4. 用户态 syscall 回到内核，在 [`handle_syscall`](https://github.com/tock/tock/blob/800bec574f107bb01b86b8898217d688c75ea181/kernel/src/kernel.rs#L739-L809) 分发（`command` 到 driver，`allow/subscribe/memop/yield` 由内核路径处理）。
