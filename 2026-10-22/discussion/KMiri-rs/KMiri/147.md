# KMiri：适配 TockOS qemu_rv64_virt

TockOS 适配了 40+ 个板子（平台为 arm 和 riscv），KMiri 选择先适配 qemu_rv64_virt，通过配置文件的方式拓展到其他板子。

* 添加 miri_start 解释器入口
  * https://github.com/KMiri-rs/tock/pull/1
* 添加 `-Zkmiri-toml` 参数，识别内存布局符号
  * https://github.com/KMiri-rs/miri/pull/38
  * https://github.com/KMiri-rs/tock/pull/2

```toml
# kmiri.toml
total_mem_size = 0x80400000

[layout]
_stext = 0x80000000
_etext = 0x8001b600
_sflash = 0x80000000
_eflash = 0x80200000
_sapps = 0x80100000
_eapps = 0x80200000
_ssram = 0x80200000
_esram = 0x80400000
_sappmem = 0x8021b680
_eappmem = 0x80400000
```

# KMiri：周一 TIS 交流会

时间：10:00 - 11:40

纪要：
* TIS 和 KMiri 无法结合，前者采用基于数值的抽象解释，后者采用中间表示的解释执行，处于不同的角度，没有结合的必要
* KMiri 和 LLM 结合的方向：Fuzzing、提高代码测试覆盖率
* 目前 KMiri 的有些检测结果只在 fork 上修复，尚未同步到星绽主分支；将 KMiri 逐步集成到星绽，是一个外部人员容易介入的参与点

# KMiri：周五双周会

时间：10:00 - 11:00

上周 KMiri 将 TockOS 的 kernel 目录的单元测试跑通，发现与 Miri 的兼容性是一个重要的事项，因为这保证了 KMiri 添加的代码没有违反 Miri 原有的检测功能。但澄钧认为需要开关控制 KMiri 用于分析内核代码还是用户态代码，但我目前不认为这是一个问题，因为无需修改代码即可解释标准库的测试框架运行的代码。

和澄钧一起分析 TockOS 的代码特点，以及初步探讨适配 KMiri 的难点。TockOS 有清晰的内存布局上，并且依赖硬件保障内存安全性。KMiri 对内存的分类和访问检测可以在无需硬件的情况下实现类似的内存检查。澄钧主要担心 TockOS 难以添加 mirch 抽象层、屏蔽外设代码。

我们一致认为，KMiri 对 TockOS 的良好支持，将意味着 KMiri 具有相当强的拓展性，可以配置不同的内存布局、处理是否支持页表。
