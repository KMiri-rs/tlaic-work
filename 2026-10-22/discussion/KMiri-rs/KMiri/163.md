## Body

> PLIC 和 CLINT 是什么

两者都是 RISC-V 系统中的标准硬件中断控制器，通过 MMIO（内存映射 I/O）访问。

## CLINT — Core Local Interruptor

**负责**：CPU 核内部的定时器中断和核间中断（IPI）。

内存布局（地址 `0x200_0000`）：
```
0x2000000  msip[0]     ← 软件中断（核间中断 IPI），每核 4 字节
0x2000004  msip[1]
...
0x2004000  mtimecmp[0] ← 定时器比较值，每核 8 字节（写入触发/清除定时器中断）
0x2004008  mtimecmp[1]
...
0x200BFF8  mtime       ← 全局单调计数器，一直递增
```

**工作原理**：当 `mtime >= mtimecmp[hart_id]` 时，硬件自动将 `mip.mtimer` 位置 1，触发定时器中断。内核清除中断的方式是**写一个更大的值**到 `mtimecmp`。

---

## PLIC — Platform-Level Interrupt Controller

**负责**：来自外设的外部中断（串口、网卡、磁盘等）。

类似 x86 的 APIC，是一个仲裁器，将多个外设中断线路汇聚到每个 CPU 核的单根 MEI（Machine External Interrupt）线。

```
外设 UART ──┐
外设 Disk ──┼──→ PLIC ──→ mip.mext 位 ──→ CPU 处理
外设 NIC  ──┘
```

内存布局（地址 `0x0c00_0000`）：
```
0x0c000000  priority[src]  ← 每个中断源的优先级（0=禁用）
0x0c001000  pending[word]  ← 哪些中断源当前有待处理信号（只读）
0x0c002000  enable[ctx]    ← 每个 hart/mode 上下文启用哪些中断源
0x0c200000  threshold[ctx] ← 该 hart 的中断优先级阈值
0x0c200004  claim/complete ← 读：获取最高优先级中断号；写：通知已处理完毕
```

---

## 两者的关系

```
┌─────────────┐    mip.mtimer    ┌─────────────┐
│    CLINT     │ ──────────────→ │             │
│  (定时器/IPI) │                 │  CPU (hart) │
└─────────────┘    mip.mext      │             │
┌─────────────┐ ──────────────→ └─────────────┘
│    PLIC      │
│  (外设中断)   │
└─────────────┘
```

在 `has_pending_interrupts` 里，两个分支分别对应这两条路径：
- `CSR.mip.is_set(mip::mtimer)` → 查询 CLINT 是否触发了定时器中断
- `self.plic.get_saved_interrupts()` → 查询 PLIC 是否有外设中断待处理
