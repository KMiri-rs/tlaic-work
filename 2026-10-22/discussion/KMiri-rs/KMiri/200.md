# Miri catches a write to a `static` without `UnsafeCell`

- **Category**: General

## Body

A minimal, dependency-free reproduction of [asterinas issue #3871](https://github.com/asterinas/asterinas/issues/3871),
checked under [Miri](https://github.com/rust-lang/miri) to confirm the Undefined Behavior is real.

## The problem

In asterinas, the x86 userspace-entry path runs assembly that writes the TSS
stack pointer straight into the `LOCAL_TSS` static:

```asm
mov gs:4, rsp   # store kernel rsp -> TSS.sp0
```

`LOCAL_TSS` lives in a `StaticStorage<T>` that has **no `UnsafeCell`**:

```rust
struct StaticStorage<T: 'static>(T);
```

So from Rust's point of view that memory is immutable. The hardware write
therefore violates the aliasing rules — it is Undefined Behavior — even though
the compiler can never prove it itself, because the write happens in assembly.
The issue notes this establishes UB every time the BSP takes the
userspace-entry path.

## Minimal reproduction (`src/main.rs`)

The assembly write is spelled out as an equivalent raw-pointer store so that
Miri can "see" the aliasing violation (Miri rejects real `asm!` blocks, so the
raw-pointer form is what makes the program miri-testable): [playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&gist=abe44aa55ee45ad26b54a446a1c89591)

```rust
use core::ptr;

/// Replicates asterinas' `StaticStorage<T>`: a plain wrapper, no interior
/// mutability markers.
struct StaticStorage<T: 'static>(T);

static LOCAL_TSS: StaticStorage<u64> = StaticStorage(0);

fn main() {
    // Equivalent to `mov gs:4, rsp` — write the kernel stack pointer into
    // the static. UB: `LOCAL_TSS` is an immutable static (no `UnsafeCell`).
    let ptr = ptr::addr_of!(LOCAL_TSS).cast_mut().cast::<u64>();
    unsafe {
        *ptr = 0x1_0000_0000_0000; // sp0 (kernel stack top)
    }

    // SAFETY: reading back a plain `u64` from a valid, aligned address.
    println!("tss.sp0 = {:#x}", unsafe {
        ptr::addr_of!(LOCAL_TSS).cast::<u64>().read_unaligned()
    });
}
```

The Rust Reference declares this exact pattern UB: mutating a static whose type
has no `UnsafeCell`, even through a raw pointer, is undefined behavior.

## Miri output

```rust
$ cargo miri run

error: Undefined Behavior: writing to alloc1 which is read-only
  --> src/main.rs:41:9
   |
41 |         *ptr = 0x1_0000_0000_0000; // sp0 (kernel stack top)
   |         ^^^^^^^^^^^^^^^^^^^^^^^^^ Undefined Behavior occurred here
   |
   = help: this indicates a bug in the program: it performed an invalid
     operation, and caused Undefined Behavior
   = help: see https://doc.rust-lang.org/nightly/reference/behavior-considered-undefined.html
     for further information
```

Miri treats a `static` without `UnsafeCell` as read-only memory, so any write is
flagged immediately — confirming the issue's analysis.

## The fix (`src/bin/fixed.rs`)

Wrap the value in `UnsafeCell` to grant interior mutability, exactly the fix the
issue suggests ("wrapping the segment in interiorly mutable types"): [playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&gist=2481e8a523a0170f4b547c5f7af45fcd)

```rust
use core::cell::UnsafeCell;

struct StaticStorage<T: 'static>(UnsafeCell<T>);

unsafe impl<T: Send> Send for StaticStorage<T> {}
unsafe impl<T: Sync> Sync for StaticStorage<T> {}

static LOCAL_TSS: StaticStorage<u64> = StaticStorage(UnsafeCell::new(0));

fn main() {
    let ptr = core::ptr::addr_of!(LOCAL_TSS).cast::<UnsafeCell<u64>>();
    // SAFETY: `UnsafeCell` grants interior mutability; this mirrors the
    // `mov gs:4, rsp` write from `syscall.S`.
    unsafe {
        *(*ptr).get() = 0x1_0000_0000_0000;
    }

    // SAFETY: read back through the same `UnsafeCell`.
    println!("tss.sp0 = {:#x}", unsafe { *(*ptr).get() });
}
```

```text
$ cargo miri run --bin fixed

tss.sp0 = 0x1000000000000
```

Miri runs the fixed version cleanly and the program executes normally.

## Run it

```text
cargo miri run               # reproduces the UB
cargo miri run --bin fixed   # verifies the fix
```
