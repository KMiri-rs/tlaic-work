# 为什么读取未初始化的字节是 UB？但复制它们不是？

- **URL**: https://github.com/orgs/KMiri-rs/discussions/236
- **Category**: General
- **Author**: zjp-CN
- **Created**: 2026-10-07T06:44:02Z
- **Updated**: 2026-10-07T06:47:09Z

## Body

核心在于:未初始化的字节**不是一个值**,而是「缺少值」。复制操作关心的是字节的**存在位置**,读取操作关心的却是字节的**内容**——后者在一个空位上没有定义。

## 一、模型:每个字节是 (value, init) 二元组

Miri(以及 Rust 参考模型)里,内存不是「一串数字」,而是每个字节附带一个 `init` 标志:

```
字节 = ( value: u8, init: bool )
        ↑ 真正的数值     ↑ 是否写过 / 有定义
```

- 写操作:设置 `value` 并把 `init` 置 `true`。
- 未初始化:`init = false`,`value` 那一栏**根本不存在**。

所以「未初始化」不是「存着一个随机数」,而是「这个格子是空的」。

## 二、复制 vs 读取:作用于元组的不同部分

| 操作                                   | 读取 `value` 字段? | 触碰 `init` 字段? | 结果                                                                   |
| -------------------------------------- | ------------------ | ----------------- | ---------------------------------------------------------------------- |
| **复制** (`ptr::copy` / move)          | 否                 | 是(照抄)          | 把整个二元组原样搬过去:空位还是空位                                    |
| **读取** (`ptr::read` / `assume_init`) | **是**             | 检查              | 要从 `value` 里**取出一个数**;但 `init=false` 时没有 `value` 可取 → UB |

关键就在这里:

- **复制只搬家,不偷看**。它关心的是「这些字节在哪」,把 `(无值, init=false)` 搬到新地址完全没问题——搬完之后新地址还是 `init=false`,空位没有凭空变成数字。
- **读取要取值**。它断言「这里有一个 `u8` 的值,我要用」。当格子是空的,「取出值」这个动作没有意义,语言于是定义为 UB。

一句话:**搬空位合法,从空位里读内容非法。**

## 三、为什么要这样设计(而不是「读出来随便给个数」)

「未初始化读取是 UB」不是数学必然,而是一个**设计取舍**。另一个可选模型是「读未初始化字节 → 返回某个任意但固定的数」(LLVM 的 `undef`)。Rust 放弃它,选了更严的模型,原因:

1. **确定性 / 可复现**。`undef` 模型下,`x == x` 都可能不成立——两次读同一个未初始化字节可以给两个不同的值。这会让程序在不同编译、不同优化级别下行为漂移,几乎无法推理。

2. **soundness(安全代码不能被 unsafe 破坏)**。设想 `MaybeUninit<bool>` 里的未初始化字节被「读成任意值」:它可能读成 `0`,也可能读成 `2`(非法的 `bool`)。让安全代码凭空得到任意值,会悄悄击穿所有类型不变量。

3. **编译器优化需要它**。如果读未初始化是 UB,编译器就能假设「合法的执行里永远不会读到未初始化数据」,从而大胆地删掉、重排某些加载。这是最干净的语义。

4. **bug 可被检测**。Miri 就是靠「读到未初始化 = 立刻报 UB」来抓 `unsafe` 里的漏洞的。若读出来是任意数,`use-after-free`、漏初始化这类 bug 就静默通过、埋雷到生产环境。

反过来,**复制必须被允许**,否则 `MaybeUninit` 连存在的意义都没有:

```rust
let m = MaybeUninit::<u8>::uninit(); // 造一个「空位」——合法
let m2 = m;                          // 搬这个空位——合法,否则你连变量都传不了
let x = unsafe { m.assume_init() };  // 从空位里读值——这才是 UB 边界
```

`MaybeUninit` 的全部价值就在于:**未初始化数据可以安全地搬来搬去,只有「解释成值」那一步才危险**。复制是前者,读取是后者。

## 四、LLVM 术语对照(可选)

LLVM 区分两个层次,恰好对应上面两种模型:

- `undef` —— 任意值,每次使用可能不同(可读,但值不确定)。
- `poison` —— 使用它即 UB(只能搬,不能「用」)。

Rust 的未初始化内存**不是 `undef`,而是 poison 语义**:搬动合法,「使用(读取成值)」即 UB。Miri 的 init-mask 就是 poison 的一种实现。
