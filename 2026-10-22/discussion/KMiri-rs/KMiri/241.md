# BlueOS 的 defconfig 功能

## Body

`defconfig` 是这套 Kconfig 体系里的**配置值种子**：`Kconfig` 树只负责*定义*有哪些配置项（类型、默认值、依赖关系），而 defconfig 按"板子 × 构建类型"给出*选定的值*。上面就是刚生成的实物，整条管线是：

```
Kconfig 树(定义符号)  +  defconfig(选值)
        │ kconfiglib 合并: load_config(defconfig) → write_config
        ▼
   gen/.config(最终配置)
        ├── generate_c_header → autoconf.h → bindgen/parse_const → blueos_kconfig 的 kconfig.rs 常量
        └── generate_rustflags_file → rustflags.txt → rustc 的 --cfg
              (bool=y → --cfg 名字小写；string → --cfg allocator="tlsf"；int 不产生 cfg，只进常量)
```

代码里随后就用 `#[cfg(allocator = "slab_dynamic")]`、`cfg(allocator_tlsf)` 这类条件编译选实现。

**具体配置的东西，按类别（都是本仓库真实符号）：**

| 类别            | 符号举例                                                                                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 硬件/内存布局   | `SRAM_SIZE`、`SRAM_BASE_ADDRESS`、`FLASH_*`、`KERNEL_VIRT_OFFSET`、`STACK_SIZE`；board Kconfig 的 `SOC_*` 还负责 `select RISCV / HAS_PLIC / HAS_MTIME`（架构与中断控制器能力） |
| **分配器选型**  | `ALLOCATOR_TLSF / SLAB / SLAB_DYNAMIC / LLFF`（choice）→ `CONFIG_ALLOCATOR="tlsf"`；`SLAB_DEBUG`、`SLAB_DYNAMIC_MAX_TOTAL_PAGES`、`ALLOCATOR_BUDDY`                            |
| 内核基本行为    | `ALIGN_SIZE`、`TICKS_PER_SECOND`、`SMP`/`NUM_CORES`、`USE_KERNEL_BOOT`、`ENABLE_SYSCALL`、`FDT`/`VIRTIO`、串口 FIFO 大小                                                       |
| 调度器          | `ROUND_ROBIN`/`ROBIN_SLICE`、`THREAD_PRIORITY_256`、`MAIN_THREAD_PRIORITY`、`KERNEL_ASYNC`                                                                                     |
| 子系统开关      | `SOFT_TIMER`、`EVENT_FLAGS`、`ENABLE_VFS`、`PROCFS`、`ENABLE_NET`（+ smoltcp 各缓冲区数量）、`THREAD_STATS`                                                                    |
| 调试/运行时检查 | `OVERFLOW_CHECK`、`STACK_HIGHWATER_CHECK`、`DEBUGGING_SCHEDULER`、各线程栈大小、`LOG_LEVEL_*`                                                                                  |

**为什么按 `<board>/<build_type>/defconfig` 组织**：同一份代码在不同板子、不同构建类型下要编成不同样子。上面的 diff 就是活例子——qemu_riscv64 的 debug 用 `slab_dynamic` 分配器、开 `THREAD_STATS`，release 改用 `tlsf`、关掉统计。defconfig 就是这些差异的载体。

**回到 `miri_test_allocator`**：这里传 `minimal.defconfig` 的作用是把 host/miri 环境的取向钉死——TLSF=y（对应被测的 `tlsf.rs`）、单核、无 SMP、关掉 VFS/NET 这些解释执行不需要的子系统。就当前这个测试而言，值本身其实无所谓（`tests.rs` 没有任何 cfg 依赖，Kconfig 的 choice 默认值反正也是 TLSF）；它更多是保证确定性，以及满足构建图对"defconfig 文件必须存在"的要求。想交互调整的话，GN 里还有现成的 `//kernel/kconfig:menuconfig` target（菜单式改 `.config`）。
