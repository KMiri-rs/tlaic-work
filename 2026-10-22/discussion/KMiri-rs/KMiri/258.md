# R4L: 跑在 Miri 上的难点

- **URL**: https://github.com/orgs/KMiri-rs/discussions/258
- **Category**: General
- **Author**: zjp-CN
- **Created**: 2026-10-12T13:12:27Z
- **Updated**: 2026-10-12T14:34:18Z
- **Comments**: 2

## Body

**1) asm / global_asm：依赖真实架构与链接布局**
- 内核 Rust 层直接封装 `asm!`，并带架构语法约束（x86 `att_syntax`）：[`rust/kernel/lib.rs:248`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/kernel/lib.rs#L248)
- `BUG/WARN`、`jump label` 会把架构相关汇编片段塞进特定节区：[`rust/kernel/bug.rs:35`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/kernel/bug.rs#L35)、[`rust/kernel/jump_label.rs:51`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/kernel/jump_label.rs#L51)
- 模块宏还会生成 `global_asm!` 的 initcall 相关符号：[`rust/macros/module.rs:592`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/macros/module.rs#L592)

**2) FFI 到内核 C：Miri 不会执行 Linux 内核实现**
- Rust IRQ 注册最终调用 C API `request_irq/free_irq`：[`rust/kernel/irq/request.rs:200`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/kernel/irq/request.rs#L200)、[`rust/kernel/irq/request.rs:232`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/kernel/irq/request.rs#L232)
- 对应 helper 就是直接进内核中断子系统：[`rust/helpers/irq.c:5`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/helpers/irq.c#L5)
- 屏障/原子也大量依赖 C 宏与架构原语（`smp_mb/xchg/try_cmpxchg`）：[`rust/helpers/barrier.c:35`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/helpers/barrier.c#L35)、[`rust/helpers/atomic_ext.c:52`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/helpers/atomic_ext.c#L52)

**3) 中断语义：需要真实 hardirq/threaded-irq 上下文**
- IRQ trait 明确 `handle` 在 interrupt context：[`rust/kernel/irq/request.rs:38`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/kernel/irq/request.rs#L38)
- 回调是 `unsafe extern "C"`，由内核异步触发：[`rust/kernel/irq/request.rs:243`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/kernel/irq/request.rs#L243)、[`rust/kernel/irq/request.rs:461`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/kernel/irq/request.rs#L461)
- 本地中断开关直接落到内核原语：[`rust/kernel/interrupt.rs:52`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/kernel/interrupt.rs#L52)、[`rust/helpers/interrupt.c:5`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/helpers/interrupt.c#L5)

**4) 并发原语：依赖 LKMM + SMP + 锁实现**
- `SpinLock` 后端调用内核 `spin_lock/spin_unlock`：[`rust/kernel/sync/lock/spinlock.rs:122`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/kernel/sync/lock/spinlock.rs#L122)、[`rust/kernel/sync/lock/spinlock.rs:129`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/kernel/sync/lock/spinlock.rs#L129)
- C helper 里有 `spin_lock_irq_disable` 这类“锁+中断状态”耦合操作：[`rust/helpers/spinlock.c:40`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/helpers/spinlock.c#L40)
- Rust 原子接口文档也明确其竞态语义对齐 LKMM：[`rust/kernel/sync/atomic.rs:171`](https://github.com/torvalds/linux/blob/551c722f40809618230001baccf219193e22fc5a/rust/kernel/sync/atomic.rs#L171)
