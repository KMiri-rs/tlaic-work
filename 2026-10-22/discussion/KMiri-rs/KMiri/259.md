# Rust for Linux: crate 依赖关系

## Body

读完 `rust/Makefile` 后，crate 之间的依赖其实是从两处信息“拼”出来的，两处必须一致：

1. **`--extern <crate>` 参数**（在 `xxx-flags` 或 `private rustc_target_flags` 里）—— 声明编译时需要链接哪些 crate。
2. **规则里的前置目标（prerequisites）**（`$(obj)/xxx.o`、`$(obj)/host/libxxx.rlib`、`$(obj)/$(libxxx_name)`）—— 保证被依赖的 crate 先编译出来。

其中：
- `--extern ffi`（不带路径）靠 `-L$(objtree)/$(obj)` 自动找到 `libffi.rlib`；
- host 侧的 rlib 靠 `-L$(objtree)/$(obj)/host` 找到；
- proc-macro（`.so`）用完整路径 `--extern pin_init_internal=$(objtree)/$(obj)/$(libpin_init_internal_name)`。

整体可以分成两组独立的依赖树：

## 1. host 侧：proc-macro 支撑 crate（编译成 rlib，供 proc-macro 用）

```
proc_macro2  (src/proc-macro2/lib.rs)          [无依赖]
   └─> quote          (src/quote/lib.rs)        --extern proc_macro2     (607 行)
          └─> syn     (src/syn/lib.rs)          --extern proc_macro2 + quote  (612 行)
```

规则：`$(obj)/host/libproc_macro2.rlib` / `libquote.rlib` / `libsyn.rlib`（599–613 行）。

## 2. proc-macro crate（编译成 `.so`，依赖上面的 host rlib）

```
                       proc_macro2 + quote + syn
                          /        |          \
zerocopy_derive  (src/zerocopy-derive/lib.rs)   --extern proc_macro2/quote/syn  (627–631 行)
macros           (src/macros/lib.rs)            --extern proc_macro2/quote/syn  (633–637 行)
pin_init_internal(src/pin-init/internal/src/lib.rs) 同左                        (639–642 行)
```

## 3. kernel 侧：真正的内核对象 crate（编译成 `.o`/rlib）

```
core              (sysroot 源码 RUST_LIB_SRC/core/src/lib.rs)   [无依赖]  (739 行)
 └─> compiler_builtins  (src/compiler_builtins.rs)  依赖 core.o               (749 行)
      ├─> zerocopy      (src/zerocopy/src/lib.rs)   依赖 compiler_builtins.o   (756 行)
      ├─> pin_init      (src/pin-init/src/lib.rs)   依赖 compiler_builtins.o
      │                                              + pin_init_internal + macros  (761 行)
      ├─> build_error   (src/build_error.rs)        依赖 compiler_builtins.o   (770 行)
      └─> ffi           (src/ffi.rs)                依赖 compiler_builtins.o   (774 行)
             ├─> bindings (src/bindings/lib.rs)      --extern ffi + pin_init   (778 行)
             └─> uapi     (src/uapi/lib.rs)          --extern ffi + pin_init   (786 行)

kernel            (src/kernel/lib.rs)
    --extern ffi --extern pin_init --extern build_error --extern macros
    --extern bindings --extern uapi --extern zerocopy --extern zerocopy_derive
    依赖: build_error.o pin_init.o macros bindings.o uapi.o
          zerocopy.o zerocopy_derive                      (793–799 行)
```

注意 `bindings.o` / `uapi.o` 还依赖 bindgen 生成的文件（`bindings_generated.rs`、`bindings_helpers_generated.rs` / `uapi_generated.rs`，781/790 行），这些又是 C 头文件的产物（525–551 行）。

## 4. 汇总成一张全景图

```
                    proc_macro2 ──> quote ──> syn
                      │   └──────────┼──────────┘
                      │         ┌────┼────┐
                      │   zerocopy_derive │  pin_init_internal
                      │              │   macros
                      │              │     │
core ─> compiler_builtins             │     │
          │  │  │  │                  │     │
          │  │  │  └──── ffi ──> bindings │
          │  │  │                └─> uapi   │
          │  │  └────── build_error         │
          │  └───────── zerocopy ───────────┤
          └──────────── pin_init ◄──────────┘
                             │
                    kernel ◄──┘（还依赖 bindings/uapi/build_error/macros/zerocopy/zerocopy_derive）
```

要“拼”依赖关系时，最快的方法就是：**顺着每个 `$(obj)/*.o` 规则的 `rustc_target_flags` 读 `--extern` 列表，再对照该规则的 prerequisites 列表**——二者一一对应，前者告诉你“依赖谁”，后者告诉你“谁先谁后”。

需要我帮你写一个脚本，自动从 Makefile 里解析出这份依赖图（比如输出成 `dot` 格式可视化）吗？
