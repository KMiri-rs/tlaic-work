# RedoxOS 有页表模拟机制作为测试

## Body

rmm 里的 emulation 机制就是把「真实 MMU 的硬件页表翻译」用软件模拟出来，让同一套页表管理代码（`PageMapper`/`PageTable`/`PageEntry`）能在没有真实硬件、甚至是在普通 `std` 环境下跑起来做测试。核心都在 [emulate.rs](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/emulate.rs)，由 [mod.rs:8-9](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/mod.rs#L8-L9) 的 `#[cfg(all(feature = "std", target_pointer_width = "64"))]` 控制编译，通过 [main.rs](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/main.rs) 这个测试 bin 驱动。

## 1. 分层：物理内存只是一块字节数组

`EmulateArch` 不接触任何硬件，它背后是一个 `Machine<A>` 结构（[emulate.rs:153](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/emulate.rs#L153)）：

```rust
struct Machine<A> {
    memory: Box<[u8]>,                          // 模拟的物理内存
    map: BTreeMap<VirtualAddress, PageEntry<A>>, // 页表翻译缓存
    table_addr: PhysicalAddress,                 // 相当于 CR3
    ...
}
```

- **物理层**：[read_phys/write_phys](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/emulate.rs#L170-L196) 就是对一个 `Box<[u8]>` 做带越界检查的裸指针读写，模拟总线上的内存访问。
- **虚拟层**：[translate](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/emulate.rs#L212) 按页对齐地址去 `map` 里查一个 `PageEntry`，得到物理页基址再加页内偏移，返回 `(物理地址, flags)`。

所以 `EmulateArch` 覆盖 `Arch` 里那几个默认的裸指针实现（[mod.rs:72-85](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/mod.rs#L72-L85) 默认直接解引用地址），全部改成走 `Machine`：

```rust
unsafe fn read<T>(address) -> T { MACHINE.lock()...read(address) }   // [emulate.rs:84](...)
unsafe fn write<T>(address, value) { ... }                            // [emulate.rs:89](...)
unsafe fn write_bytes(...) { ... }                                    // [emulate.rs:99](...)
```

`read`/`write` 还额外做了「不跨页边界」的断言（[emulate.rs:220-258](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/emulate.rs#L220-L258)），并检查 `flags.has_write()` 才允许写，模拟缺页/只读页会 `panic!`。

## 2. 页表 walk 才是真正的"模拟 MMU"

`map` 只是一份缓存。真正把页表结构（PML4→PDP→PD→PT）翻译成虚拟→物理映射的是 [invalidate_all](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/emulate.rs#L293)。它从 `table_addr`（即 CR3）出发，逐级用 `read_phys::<usize>` 读表项：

- 遍历 PML4 的 512 项 → 解出 PDP 地址 → 遍历 512 项 → PD → PT → 叶子页；
- 用硬编码的位移 `(i4 << 39) | (i3 << 30) | (i2 << 21) | (i1 << 12)`（[emulate.rs:337](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/emulate.rs#L337)）反推出虚拟页号；
- 把每个 present 的叶子 `PageEntry` 塞进 `map`。

这套位移跟 `X8664Arch` 的 4 级、每级 9 位完全一致——`EmulateArch` 直接复用了 `X8664Arch` 的所有常量（[emulate.rs:58-81](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/emulate.rs#L58-L81)）。之后 `translate` 就是一次 `BTreeMap` 查表，相当于 TLB 命中。

`set_table`（[emulate.rs:351](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/emulate.rs#L351)）就是 `mov cr3` 的软件版：改 `table_addr` 后立即 `invalidate_all()` 重建缓存，和 [x86_64.rs:62](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/x86_64.rs#L62) 的 `mov cr3` 语义对应。而单页 `invalidate`（[emulate.rs:288](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/emulate.rs#L288)）故意 `unimplemented!`，说明目前测试流程只用全量刷新（`PageFlushAll`，见 [flush.rs:52](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/page/flush.rs#L52) 的 `Drop` → `invalidate_all`）。

## 3. 启动时的 bootstrap

`EmulateArch::init()`（[emulate.rs:14](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/emulate.rs#L14)）在模拟内存里手工搭一张最小页表，把 pml4/pdp/pd/pt 依次放在物理 0、4096、8192、12288：

- PML4 的第 256 项（对应 `PHYS_OFFSET = 0xFFFF_8000_0000_0000`，即高半区起点）→ PDP；
- PDP[0] → PD，PD[0] → PT；
- PT 的 512 项 → 前 2 MiB 物理页，**恒等映射**（[emulate.rs:36-43](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/emulate.rs#L36-L43)）。

于是内核在 `PHYS_OFFSET` 处就能访问到物理内存（包括页表自身），完成初始化。返回的 `MEMORY_AREAS`（[emulate.rs:139](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/arch/emulate.rs#L139)）把最前面 4 页（被 bootstrap 页表占掉）从可分配区里剔除，其余 64 MiB 分成两半，后一半标注 "for debugging"。

## 4. 它服务的目的

`README.md` 一句点题：这个 crate 提供硬件内存管理的抽象，并**附带一个用软件模拟来测试内存管理的机制**。[main.rs:276](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/main.rs#L276) 里 `EmulateArch::init()` 之后跑的正是完整流程——用 `BumpAllocator`/`BuddyAllocator` 建页表、`map_linearly` 把物理内存映射到 `PHYS_OFFSET`、`make_current` 切表、然后 `map_phys`/`unmap_phys` 反复映射解除映射、最后直接 `EmulateArch::read/write` 验证（[main.rs:285-307](https://github.com/KMiri-rs/Redox/blob/b68957d4a3e1590c4f5b8d5608d94b3e45bd3b45/rmm/src/main.rs#L285-L307)）。这些代码和真实内核用的完全同一套 `PageMapper`，只是把 `Arch` 从 `X8664Arch` 换成了 `EmulateArch`，就能在宿主机上无硬件、可断点地跑起来，等价于在裸机上验证页表逻辑。

一句话总结：**EmulateArch 用 `Box<[u8]>` 当物理内存、用软件 walk 当 MMU，让页表这套数据结构成为"模拟机器"里可读可写的数据，从而在 `std` 环境下复用并测试真实的页表管理代码。**
