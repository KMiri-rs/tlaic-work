## Body

`Allocation` 来自 rustc 的 `rustc_const_eval::interpret`（在本项目里通过 `pub use rustc_const_eval::interpret::*;` 引入）。它的定义在 rustc 源码 `compiler/rustc_middle/src/mir/interpret/allocation.rs`，是一个三泛型结构体：

```rust
pub struct Allocation<Prov: Provenance = CtfeProvenance, Extra = (), Bytes = Box<[u8]>> {
    bytes: Bytes,                        // 实际字节内容
    provenance: ProvenanceMap<Prov>,     // 指针出处映射
    init_mask: InitMask,                 // 初始化位掩码
    pub align: Align,                    // 对齐
    pub mutability: Mutability,          // 可变性
    pub extra: Extra,                    // 机器扩展状态
}
```

## 各字段含义

1. **`bytes: Bytes`** —— 分配内存的**实际字节内容**。注意：如果某个字节属于一个指针，这些字节代表的是该指针的**偏移量（offset）**，真正的指针出处放在 `provenance` 里。

2. **`provenance: ProvenanceMap<Prov>`** —— 从字节地址到指针出处数据的**映射表**。只把每个指针的**首字节**登记进表里，即每个表项作用于从该偏移开始的 `pointer_size` 个连续字节（pointer-tag 逐字节模型）。

3. **`init_mask: InitMask`** —— 一个**位掩码**，标记该分配里**哪些字节已初始化**。有一个不变量：**未初始化的部分不允许带 provenance**。这正是 `physical_mem.rs` 里 `init_masks` 字段利用的部分。

4. **`pub align: Align`** —— 对齐值（保证是 2 的幂），用于检测**非对齐访问**。

5. **`pub mutability: Mutability`** —— 分配是否可变（`Mut` / `Not`）。codegen 也用它判断 `static mut` 是否放进可变内存。

6. **`pub extra: Extra`** —— 留给**具体机器（machine）** 的扩展状态（默认为 `()`，即无额外状态）。

## 泛型参数与本项目的实例化

三个泛型参数：

| 参数                      | 默认值           | 本项目里的取值                          |
| ------------------------- | ---------------- | --------------------------------------- |
| `Prov`（provenance 类型） | `CtfeProvenance` | `Provenance`（Miri 的指针出处）         |
| `Extra`（机器扩展）       | `()`             | `()`（无扩展状态）                      |
| `Bytes`（字节容器）       | `Box<[u8]>`      | `MiriAllocBytes`（Miri 自定义字节存储） |

所以在 `physical_mem.rs` 里写成 `Allocation<Provenance, (), MiriAllocBytes>`（第 61、396 行），即「Miri 出处 + 无扩展 + Miri 字节容器」的分配。

## 与本问题的关系

`init_masks` 字段里存的就是这种 `Allocation`，但它在那个场景下**只关心两个维度**：

- `init_mask()`：记录物理页哪些字节已初始化（核心用途）；
- `provenance()`：`physical_copy` 里用它检查某页是否带指针出处（带的话就拒绝纯字节拷贝，见 `physical_mem.rs:257`）。

字节内容 `bytes` 本身只是「影子」的载体，并不作为物理内存的真相来源——真正的物理字节在 `PhysicalMemory::mem` 那块裸缓冲区里。
