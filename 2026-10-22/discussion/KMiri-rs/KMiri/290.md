# Run `rust_minimal` on User-mode Linux: invalid module format

## Body

```Makefile
.PHONY: uml-rust-minimal
uml-rust-minimal:
	make ARCH=um LLVM=1 defconfig
	./scripts/config --enable RUST
	./scripts/config --enable MODULES
	./scripts/config --enable SAMPLES
	./scripts/config --enable SAMPLES_RUST
	./scripts/config --module SAMPLE_RUST_MINIMAL
	./scripts/config --enable BLK_DEV_INITRD
	./scripts/config --enable RD_GZIP
	./scripts/config --enable DEVTMPFS
	./scripts/config --enable DEVTMPFS_MOUNT
	./scripts/config --enable BINFMT_ELF
	./scripts/config --enable BINFMT_SCRIPT
	make ARCH=um LLVM=1 olddefconfig
	make -j"$$(nproc)" ARCH=um LLVM=1 linux samples/rust/rust_minimal.ko
	./initramfs.sh
	timeout --foreground 90 ./linux umid=rust-minimal mem=512M initrd=/tmp/initramfs-rust.cpio.gz rdinit=/init con0=fd:0,fd:1 || test $$? -eq 124
```


```
$ make uml-rust-minimal
=== insmod rust_minimal.ko ===
subarch: rust_minimal: Unknown rela relocation: 9
subarch: rust_minimal: Unknown rela relocation: 9
insmod: can't insert '/rust_minimal.ko': invalid module format
insmod failed: 8
```

这是 **UML + Rust 模块重定位类型不匹配** 导致的。

- `rela relocation: 9` 在 x86_64 上就是 `R_X86_64_GOTPCREL`（即通过 GOT 的 PC 相对重定位）：`arch/x86/um/asm/elf.h:85`
- 但 x86 模块加载器只处理 `NONE/64/32/32S/PC32/PLT32/PC64`，没有处理 `GOTPCREL`，遇到就直接报错并返回 `-ENOEXEC`：`arch/x86/kernel/module.c:118`、`arch/x86/kernel/module.c:144`
- 返回 `-ENOEXEC` 后，用户态 `insmod` 就显示 `invalid module format`，并返回 `8`（你看到的 `insmod failed: 8`）

为什么会出现 `GOTPCREL`：
- 你当前是 UML 构建，`arch/um/Makefile` 强制了 Rust `-Crelocation-model=pie`：`arch/um/Makefile:65`
- PIE 代码更容易生成 `GOTPCREL`，而当前内核模块加载路径不接受该类型，所以失败。

为什么日志打印两次：
- 常见是 `insmod` 的加载路径会尝试两次（或内核在不同重定位阶段触发同类报错），因此同一错误出现两行；核心原因仍是“不支持重定位 9”。

如果你只是想在 UML 验证 sample，最稳妥是把 `SAMPLE_RUST_MINIMAL` 改成内建（`=y`）而不是模块（`=m`）。我可以直接给你加一个 `uml-rust-minimal-builtin` 目标。
