# 总结

## Rust for Linux：KMiri 通过 binding passthrough 方式解释 bitmap 单元测试

* miri 侧：新增 `kmiri_passthrough` shim 模块，经 `KMIRI_PASSTHROUGH_DIR` 及可选 proc 端点传输请求/响应，并接入 foreign item 回退分发：
  * https://github.com/KMiri-rs/miri/pull/67
* linux 侧：UML 内置 `SAMPLE_KMIRI_PASSTHROUGH` 示例与 `/proc/kmiri_pt` 接口，新增 `miri-unit-passthrough` 目标，在 `--cfg KMIRI_BITMAP_PASSTHROUGH` 下走 bindings 路径：
  * https://github.com/KMiri-rs/linux/pull/3

## Rust for Linux：试图重现 Formatter use-after-free 问题

* （文昭）记录 KMiri 在 krealloc 可运行后仍漏报 Linux `Formatter::new` 的 use-after-free：
  * https://github.com/KMiri-rs/miri/pull/64
  * 对应 Rust-for-Linux/linux#1261

## 设计文档更新

* 用 `mdbook-spec` 加锚点、重命名文档、补齐模拟器附录表格、精简 overview 并调整架构图与 CSS：
  * https://github.com/KMiri-rs/book/pull/8
  * https://github.com/KMiri-rs/book/pull/10
  * https://github.com/KMiri-rs/book/pull/9
  * https://github.com/KMiri-rs/book/pull/11
  * https://github.com/KMiri-rs/book/pull/13
* （文昭）新增 Asterinas、TockOS、BlueOS 适配路线图；重写 core-design 章节，并新增 7 张中文 SVG 架构图：
  * https://github.com/KMiri-rs/book/pull/12

## KMiri：修复任务退出与后继任务切换

（文昭）修复 KMiri-rs/KMiri#277（退出任务若还有可运行后继，会残留解释器线程报 `main thread terminated without waiting for all remaining threads`）：

* asterinas 内核侧：退出任务先正常返回，再经 `miri_switch_to_after_return` 排队交接，清理改在继任者栈上执行：
  * https://github.com/KMiri-rs/asterinas/pull/29
* miri 侧：新增 `miri_switch_to_after_return`，仅对已注册内核任务转移 termination/join 时钟：
  * https://github.com/KMiri-rs/miri/pull/66
* KMiri 回归测试：新增 `task-exit-with-runnable`、`task-exit-last` 两个内核入口测例：
  * https://github.com/KMiri-rs/KMiri/pull/285
* 三个内核 `task-switch-back` / `task-exit-with-runnable` / `task-exit-last` 均由 exit 6 收敛到 exit 0
