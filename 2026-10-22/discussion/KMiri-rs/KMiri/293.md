# KMiri 支持 Rust for Linux - c2Rust 翻译 bindings + UML

- **Category**: General
- **Author**: zjp-CN
- **Created**: 2026-10-26T12:03:32Z
- **Updated**: 2026-10-26T12:58:08Z
- **Comments**: 2

## Body


**目标重述**
- 目标：把 Rust for Linux 相关 C binding/依赖层逐步 Rust 化，并在 user-mode 环境下落到 `libc` 后端，最终尽可能让更多 R4L Rust 代码可由 Miri 执行验证。

**阶段 0：边界定义（1–2 周）**
- 明确“不做什么”：暂不追求“完整 Linux 内核在 Miri 下运行”。
- 划分验证范围：先选 `alloc`、数据结构、同步原语包装、一个小驱动核心逻辑。
- 定义语义基线：哪些内核语义必须保真（内存分配失败、引用计数、锁语义、错误码）。
- 产出：`SCOPE.md` + 风险清单 + 首批 API 清单（20–50 个）。
- 验收：团队对“PoC 成功标准”达成一致（例如：某 Rust 子模块在 Miri 全绿）。

**阶段 1：架构拆层（2–4 周）**
- 把现有 Rust 代码拆成三层：
  - `core-logic`：纯 Rust 逻辑（目标 100% 可 Miri）。
  - `kernel-abstraction`：trait 抽象（内存、锁、时间、任务上下文、日志、原子操作包装）。
  - `backend`：`linux-kernel backend` 与 `libc-uml backend`。
- 禁止上层直接调用裸 FFI，统一走 abstraction 层。
- 产出：crate/workspace 分层 + 最小 trait 集。
- 验收：核心模块可在不链接内核头的情况下编译。

**阶段 2：最小 `libc` 后端（3–6 周）**
- 实现最小运行时：
  - 分配器（`malloc/free` 封装 + 故障注入）。
  - 线程/锁（`pthread_mutex`/`rwlock`）映射到内核抽象。
  - 时间/随机/日志/错误码映射。
- 明确“不等价”点：中断上下文、抢占、RCU 先 stub 或降级语义。
- 产出：`backend-libc` 可跑单元测试。
- 验收：核心逻辑测试在 user-space 通过，且与 kernel backend 行为一致率达到预设阈值。

**阶段 3：binding Rust 化策略（并行推进，4–12 周）**
- 不做“一次性全量 C→Rust 转译”；采用“薄层替换”：
  - 先把常用 binding 分组（types/constants/helpers/functions）。
  - 对纯声明型绑定优先改为 Rust 声明/包装。
  - 对复杂宏/inline/arch 相关内容保留 C 或做手工 Rust 重写。
- 每替换一组都跑双后端一致性测试。
- 产出：`bindings-rust` 子集逐步扩大。
- 验收：被替换 binding 的调用路径中，C 依赖比例持续下降（设 KPI）。

**阶段 4：Miri 适配与 shim（持续进行）**
- 建立 `miri-support` 层：
  - 屏蔽不支持的 FFI 入口。
  - 为必要 libc 行为提供 deterministic shim。
  - 处理原子/并发限制：优先把并发逻辑收敛为可控调度测试。
- 建立两套测试：
  - `miri-safe`（必须过，纯逻辑+可模拟部分）。
  - `native-only`（真实并发/系统调用路径）。
- 产出：可重复执行的 `cargo +miri` CI 作业。
- 验收：首个目标模块在 Miri 下稳定通过（无 UB 报告）。

**阶段 5：UML 集成验证（4–8 周）**
- 把 `libc` 后端与 UML 场景对齐（启动、基本 I/O、错误路径）。
- 做“同用例三跑”：
  - kernel backend（真实内核路径）
  - libc/UML backend（用户态）
  - Miri（受限语义）
- 产出：差异报告与语义豁免清单。
- 验收：关键用例在三环境结果可解释，偏差有文档化理由。

**阶段 6：扩面与工程化（长期）**
- 扩大子系统覆盖（驱动核心逻辑、内存管理子集、协议栈局部组件）。
- CI 分层：
  - 快速：unit + miri-safe
  - 中速：user-space integration
  - 慢速：kernel/UML 回归
- 引入质量门：新增代码必须经过 abstraction 层，禁止新增裸 C 绑定直连。
- 产出：迁移看板 + 自动统计（Rust 化比例、Miri 覆盖率、shim 数量）。

**每阶段的“停机线”（避免失控）**
- shim 数量暴涨且语义失真严重时，暂停扩面，先收敛抽象。
- 若某类内核语义无法在 `libc` 后端保持可验证一致，标记为 `native-only`，不要硬塞进 Miri。
- 任何一次大替换都必须先有最小可回滚路径。

**建议你先做的 3 个 PoC**
- PoC-1：`alloc + error handling` 路径（最容易暴露 UB/边界）。
- PoC-2：一个有状态机的 Rust 模块（验证抽象层设计是否合理）。
- PoC-3：一个轻量同步场景（mutex + refcount），测试 Miri + shim 成本。
