三篇文章全部来自 **Folkert de Vries**，属于 Trifecta Tech Foundation 的「数据压缩倡议」，主题都是把 C 写的 bzip2 算法移植/重写成 Rust。按时间顺序总结如下：

## 1. Translating bzip2 with c2rust（2025-03-10）

讲如何用 **c2rust**（Immunant/Galois 开发的 C→Rust 自动翻译工具）把 bzip2 的 C 代码翻译成 Rust，并逐步清理成「libbzip2-rs」。核心观点：

- **为什么选 c2rust**：bzip2 代码库小、无线程、平台无关（无 SIMD），是可管理的好实验对象。翻译第一天就能拿到「bug 级兼容」的代码，这是最大优势——避免手工重写时自己引入 bug。
- **清理翻译产物的典型模式**：
  - C 的 `for` 循环会被保守地翻译成 `while` 循环（因为 C 里循环变量可能被暗中修改，c2rust 无法静态判断），需要手工改回 `for`。
  - 大量冗余类型标注和 cast（如 `i++` 被翻成 `{ i += 1; i }`，多余的分号表达式）。
  - 指针算术全部用 `offset`，需要逐个确认不会越界/负索引后改成安全的 slice。
- **难点**：
  - **不可约控制流**（`goto`、`switch` 的 fall-through）在 Rust 表面语法里无法表达，c2rust 会生成带魔法数字 `current_block_1 = 4407541767199398248` 的丑陋 match，这类代码往往在性能敏感路径上。
  - `libc` 函数的翻译（如 `fopen`/`open`）丢失了条件编译和常量名，清理需要深入理解 C 和 Rust 双方语义。
- **结论**：库部分用 c2rust 极其满意（推荐）；但**二进制/stdio 密集的部分**清理成本不值，建议要么翻译后原样留着（不比原 C 更不安全），要么从零用 Rust 重写。后续打算在 zlib-rs 剩余部分继续用 c2rust。

## 2. bzip2 crate switches from C to 100% rust（2025-06-17）

宣布发布 **bzip2 0.6.0**，默认改用 Rust 实现 **libbz2-rs-sys**，替代原来的 C 依赖。要点：

- **性能**：压缩快约 10–15%，解压快约 4–10%（有几个样本只打平 C，但没有明显更慢的情况）。
- **跨编译**：彻底去掉 C 依赖后，编译到 WebAssembly/Windows/Android「直接就能用」，消除了 `cc` crate 和链接系统库时的疑难杂症，是巨大的维护收益。
- **符号默认不导出**：避免与其他依赖的符号冲突；需要导出时提供 feature flag。
- **可跑 MIRI**：unsafe 代码和高层调用方现在都能在 Miri 下运行。
- **安全审计**：Radically Open Security 审计只发现一个 off-by-one 逻辑 bug，以及 fuzzer 的几处限制，无其他重大发现。资金来自 NLnet Foundation。

## 3. Fixing our own problems in the Rust compiler（2026-03-30，最新）

讲述了在压缩项目工作中遇到 Rust 自身和工具链的限制后，团队从「干等」转向「自己修编译器」的经历。因为需求小众、等 Rust 维护者排期不现实。具体贡献：

- **Clippy**：修复了 `collapsible_if` 在括号场景下生成错误建议的 bug；新增 `ptr_offset_by_literal` lint（把 `foo.offset(4)` 改写为 `foo.add(4)`，便于后续转成 slice）；顺带清理了 `ptr_offset_with_cast` 的技术债。
- **Miri**：继续补 AVX-512 内建指令（用于 adler32 的 avx512vnni 实现）；修复了读静态函数指针数组时的 ICE；补上了缺失的 `libc::memset` 支持（否则 c2rust 产物会早退）。强调「Miri 实现只是一半工作，另一半是测试不回归」。
- **大特性**：
  - `#![feature(cfg_select)]` —— 更好的配置谓词写法，Rust 1.95 起在 std 稳定可用。
  - `#![feature(c_variadic)]` —— Rust 能调用但「定义」C 变参函数还不稳定，zlib-rs 的 C API 需要它；正推进稳定化。
- **结论**：「当你做『邪门』的事时，问题会自己找上你」——底层系统开发与编译器开发形成了良性的双向促进。

---

**整体脉络**：先用 c2rust 快速移植拿到正确实现 → 清理成 100% Rust 并发布、验证性能与安全 → 过程中反过来改进 Rust 生态（clippy、Miri、稳定特性），形成正向循环。
