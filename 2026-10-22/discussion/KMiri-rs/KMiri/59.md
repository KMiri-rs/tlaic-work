# 举例说明 Immediate::Scalar vs Immediate::ScalarPair

- **URL**: https://github.com/orgs/KMiri-rs/discussions/59
- **Category**: General
- **Author**: zjp-CN
- **Created**: 2026-06-15T10:44:31Z
- **Updated**: 2026-06-15T10:44:31Z

## Body

`Immediate` 是解释器里对“小值”的优化表示：值不一定放在模拟内存里，而是直接存在解释器的数据结构里。

大致可以理解成：

```rust
enum Immediate {
    Scalar(Scalar),
    ScalarPair(Scalar, Scalar),
    Uninit,
}
```

其中你问的两个核心变体是：

```text
Immediate::Scalar
Immediate::ScalarPair
```

---

**Immediate::Scalar**

`Immediate::Scalar(x)` 表示这个值的 ABI 表示只需要一个 scalar。

这里的 `Scalar` 可以是：

```text
整数
布尔
字符
指针
函数指针
裸地址
某些 enum 的 discriminant
```

举例：

```rust
let x: i32 = 42;
```

解释器可以把 `_x` 存成：

```text
Immediate::Scalar(42_i32)
```

不用真的分配一块 4 字节内存。

再比如：

```rust
let b: bool = true;
```

可以是：

```text
Immediate::Scalar(1_u8)
```

再比如：

```rust
let p: *const i32 = &x as *const i32;
```

可以是：

```text
Immediate::Scalar(ptr_to_x)
```

也就是说，一个 `Scalar` 足以描述这个值的运行时表示。

---

**Immediate::Scalar 的内存展开**

如果把：

```text
Immediate::Scalar(42_i32)
```

写入内存，假设目标类型是 `i32`，小端机器上内存可能类似：

```text
offset 0: 0x2a
offset 1: 0x00
offset 2: 0x00
offset 3: 0x00
```

但在解释器内部，没必要一开始就保存成这些 bytes，可以直接保存成：

```text
Scalar(42)
```

只有在必须进内存时，比如取地址、memcpy、处理 padding、按 byte 访问时，才展开成内存。

---

**Immediate::ScalarPair**

`Immediate::ScalarPair(a, b)` 表示这个值的 ABI 表示需要两个 scalar。

典型例子：

```text
胖指针
slice 引用
trait object 引用
某些两字段结构体
某些 enum / option 优化后的表示
```

最直观的例子是 slice 引用：

```rust
let arr = [10, 20, 30];
let s: &[i32] = &arr[..];
```

`&[i32]` 是胖指针。它运行时通常由两个部分组成：

```text
data pointer
length
```

所以解释器可以把 `s` 表示成：

```text
Immediate::ScalarPair(
    ptr_to_arr_first_element,
    3_usize,
)
```

也就是：

```text
a = data pointer
b = length
```

这两个 scalar 合起来表示一个 slice reference。

---

**trait object 也是 ScalarPair**

比如：

```rust
trait Draw {
    fn draw(&self);
}

let obj: &dyn Draw = &button;
```

`&dyn Draw` 通常也是胖指针，由两个部分组成：

```text
data pointer
vtable pointer
```

解释器可以表示成：

```text
Immediate::ScalarPair(
    ptr_to_button,
    ptr_to_vtable_for_button_as_Draw,
)
```

也就是：

```text
a = data pointer
b = metadata pointer / vtable pointer
```

---

**简单 struct 也可能是 ScalarPair**

例如：

```rust
#[repr(C)]
struct Pair {
    a: u32,
    b: u32,
}

let p = Pair { a: 1, b: 2 };
```

在某些 ABI/layout 决策下，它可能被表示成：

```text
Immediate::ScalarPair(
    Scalar(1_u32),
    Scalar(2_u32),
)
```

但这不是所有 struct 都会这样。更复杂、有 padding、字段更多、或者不适合寄存器传递的类型，可能会被表示成 memory layout，而不是 immediate。

---

**Immediate::Scalar vs Immediate::ScalarPair 的本质区别**

可以这样看：

```text
Immediate::Scalar(x)
  一个寄存器就能装下这个值。

Immediate::ScalarPair(a, b)
  两个寄存器才能装下这个值。
```

这和 rustc 的 ABI 分类有关。

例如：

```rust
let x: usize = 10;
```

可能是：

```text
Scalar(10)
```

而：

```rust
let s: &[u8] = &[1, 2, 3];
```

可能是：

```text
ScalarPair(ptr, len)
```

因为 slice reference 需要：

```text
一个 scalar 表示 data pointer
一个 scalar 表示 length
```

---

**具体对比表**

```text
Rust 值                      可能的 Immediate 表示

42_i32                       Scalar(42)
true                         Scalar(1)
'a'                          Scalar(0x61)
ptr: *const T                Scalar(ptr)
&x: &i32                     Scalar(ptr)

&[1, 2, 3][..]: &[i32]       ScalarPair(ptr_to_data, 3)
&dyn Trait                   ScalarPair(ptr_to_data, ptr_to_vtable)
(str slice) &str             ScalarPair(ptr_to_utf8_data, len)
(u32, u32)                   ScalarPair(1, 2) 视 layout/ABI 决定
```

---

**为什么胖指针是 ScalarPair**

普通引用：

```rust
let r: &i32 = &x;
```

只需要一个地址：

```text
r = pointer to x
```

所以：

```text
Immediate::Scalar(ptr_to_x)
```

slice 引用：

```rust
let s: &[i32] = &arr[..];
```

只存一个地址不够，因为还要知道长度。

所以它是：

```text
s = (data pointer, length)
```

因此：

```text
Immediate::ScalarPair(ptr_to_arr, len)
```

trait object 引用：

```rust
let obj: &dyn Trait = &x;
```

只存一个地址也不够，因为动态分发还要知道 vtable。

所以它是：

```text
obj = (data pointer, vtable pointer)
```

因此：

```text
Immediate::ScalarPair(ptr_to_x, ptr_to_vtable)
```

---

**内存里 ScalarPair 怎么摆放**

`Immediate::ScalarPair(a, b)` 本身只是两个 scalar：

```text
a
b
```

但如果要写进内存，必须知道 layout。

例如一个 slice：

```rust
let s: &[u8] = &[10, 20, 30];
```

在 64 位平台上，通常：

```text
a = data pointer, 8 bytes
b = length,       8 bytes
```

如果写入内存，可能是：

```text
offset 0..8   = data pointer
offset 8..16  = length
```

所以内存大小是 16 字节。

但 `ScalarPair` 写入内存的 offset 不是 `Immediate` 自己决定的，而是由 `layout` 决定的。

相关代码里：

```rust
Immediate::ScalarPair(a_val, b_val) => {
    let BackendRepr::ScalarPair(_a, b) = layout.backend_repr;
    let a_size = a_val.size();
    let b_offset = a_size.align_to(b.align(&tcx).abi);

    alloc.write_scalar(alloc_range(Size::ZERO, a_size), a_val)?;
    alloc.write_scalar(alloc_range(b_offset, b_val.size()), b_val)?;
}
```

意思是：

```text
第一个 scalar 写到 offset 0
第二个 scalar 写到 b_offset
```

而 `b_offset` 要根据 layout 中第二个 scalar 的 alignment 算。

---

**为什么 ScalarPair 特别容易和 layout 扯上关系**

因为 `Scalar` 只有一个值：

```text
Scalar(x)
```

写到内存通常就是：

```text
offset 0 = x
```

但 `ScalarPair(a, b)` 有两个值：

```text
a
b
```

写回内存时要决定：

```text
a 放哪？
b 放哪？
中间有没有 padding？
```

这就依赖 layout。

例如：

```text
layout A:
  a: offset 0, size 1
  padding: offset 1..8
  b: offset 8, size 8

layout B:
  a: offset 0, size 4
  padding: offset 4..8
  b: offset 8, size 8
```

两个 layout 都可能是 `ScalarPair`，但 `a` 的大小、`b` 的对齐、padding 位置可能不同。

`Immediate::ScalarPair(a, b)` 本身不记录这些 padding 字节。

它只记录：

```text
a_val
b_val
```

所以必须结合 layout 才能准确写成内存 bytes。

---

**一个具体 slice 例子**

Rust 代码：

```rust
let arr = [10u8, 20, 30];
let s: &[u8] = &arr;
```

解释器内部可能有：

```text
arr:
  在内存 allocation A
  A + 0 = 10
  A + 1 = 20
  A + 2 = 30

s:
  Immediate::ScalarPair(
      Scalar::Ptr(A + 0),
      Scalar::Int(3)
  )
```

这里 `s` 没必要单独分配 16 字节内存，因为它只是一个胖指针值。解释器可以直接在 local 里保存两个 scalar。

如果后面有：

```rust
let t = s;
```

且普通布局兼容，那么 `t` 也可以直接变成：

```text
Immediate::ScalarPair(A + 0, 3)
```

不需要内存拷贝。

但如果后面代码需要：

```rust
let p = &s as *const &[u8];
```

也就是要取 `s` 自己的地址，那么 `s` 必须真的在内存里。解释器会把它 force 到 memory：

```text
allocation B:
  offset 0..8   = A + 0
  offset 8..16  = 3

s:
  Operand::Indirect(B)
```

这就是 immediate 到 mplace 的转换场景。

---

**Immediate::ScalarPair 不是 tuple 的语义值**

要注意：

```text
ScalarPair(a, b)
```

不是说 Rust 源码里一定有一个二元组。

它是 ABI 层面的表示。

例如：

```rust
let s: &[u8]
```

源码类型是 slice reference，不是 tuple。

但 ABI 表示是两个 scalar：

```text
(ptr, len)
```

所以它可以是 `Immediate::ScalarPair(ptr, len)`。

反过来，一个 Rust 二元组：

```rust
let x: (u8, u64) = (1, 2);
```

也不一定总是 `ScalarPair`。它可能因为 padding、ABI、target 规则等原因被归类成 memory layout。

所以：

```text
Immediate::ScalarPair 是 ABI 分类，不是源码语法分类。
```

---

**和 `BackendRepr` 的关系**

`Immediate` 能不能是 `Scalar` / `ScalarPair`，跟 layout 的 `backend_repr` 有关。

概念上：

```text
BackendRepr::Scalar(...)
  可以用 Immediate::Scalar 表示。

BackendRepr::ScalarPair(...)
  可以用 Immediate::ScalarPair 表示。

BackendRepr::Memory { ... }
  通常必须在内存里，不能完整用 immediate 表示。
```

所以：

```rust
i32
```

常见是：

```text
BackendRepr::Scalar
Immediate::Scalar
```

```rust
&[u8]
```

常见是：

```text
BackendRepr::ScalarPair
Immediate::ScalarPair
```

```rust
[u8; 1024]
```

通常是：

```text
BackendRepr::Memory
MPlace / memory allocation
```

---

**和你前面问的 `dest.force_mplace` 的关系**

假设：

```rust
let s: &[u8] = &[1, 2, 3];
```

解释器可以保存：

```text
s = Immediate::ScalarPair(ptr, len)
```

如果只是普通赋值：

```rust
let t = s;
```

可以直接：

```text
t = Immediate::ScalarPair(ptr, len)
```

但如果是在之前那种特殊路径：

```text
src_val 是按 src.layout 读出来的 ScalarPair
src.layout 和 dest.layout 不兼容
```

那么不能简单做：

```text
dest = Immediate::ScalarPair(a, b)
```

因为以后这个 `ScalarPair` 被写入内存时，可能会按 `dest.layout` 展开。

所以必须：

```rust
let dest_mem = dest.force_mplace(self)?;
self.write_immediate_to_mplace_no_validate(
    Immediate::ScalarPair(a, b),
    src.layout(),
    dest_mem.mplace,
)
```

也就是：

```text
把 dest 变成 memory。
然后按 src.layout 把 a/b 写进去。
```

这就是 `ScalarPair` 比 `Scalar` 更容易触发“layout offset”问题的原因。

---

**最短总结**

```text
Immediate::Scalar(x)
  一个 scalar 就能表示的值。
  例子：i32、bool、char、普通指针、普通引用。

Immediate::ScalarPair(a, b)
  两个 scalar 才能表示的值。
  例子：&[T] = (data_ptr, len)，&str = (data_ptr, len)，&dyn Trait = (data_ptr, vtable_ptr)。

关键区别：
  Scalar 写入内存基本只涉及 offset 0。
  ScalarPair 写入内存必须依赖 layout 决定第二个 scalar 的 offset，所以 layout 不兼容时尤其敏感。
```

特别容易和 layout 扯上关系**\r\n\r\n因为 `Scalar` 只有一个值：\r\n\r\n```text\r\nScalar(x)\r\n```\r\n\r\n写到内存通常就是：\r\n\r\n```text\r\noffset 0 = x\r\n```\r\n\r\n但 `ScalarPair(a, b)`  padding: offset 1..8\r\n  b: offset 8, size 8\r\n\r\nlayout B:\r\n  a: offset 0, size 4\r\n  padding: offset 4..8\r\n  b: offset 8, size 8\r\n```\r\n\r\n两个 layout 都可能是 `ScalarPair`，但 `a` 的大小、`b` 的对齐、padding 位置可能不同。\r\n\r\n`Immediate::ScalarPair(a, b)` 本身不记录这些 padding 字节。\r\n\r\n它只记录：\r\n\r\n```text\r\na_val\r\nb_val\r\n```\r\n\r\n所以必须结合 layout 才能准确写成内存 bytes。\r\n\r\n---\r\n\r\n**一个具体 slice tuple。\r\n\r\n但 ABI 表示是两个 scalar：\r\n\r\n```text\r\n(ptr, len)\r\n```\r\n\r\n所以它可以是 `Immediate::ScalarPair(ptr, len)`。\r\n\r\n反过来，一个 Rust 二元组：\r\n\r\n```rust\r\nlet x: (u8, u64) = (1, 2);\r\n```\r\n\r\n也不一定总是 `ScalarPair`。它可能因为 padding、ABI、target 规则等原因被归类成 memory layout。\r\n\r\n所以：\r\n\r\n```text\r\nImmediate::ScalarPair 是 ABI 分类，不是源码语法分类。\r\n```\r\n\r\n---\r\n\r\n**和 `BackendRepr`
