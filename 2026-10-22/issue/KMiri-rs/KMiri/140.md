这 24 个失败大致是 7 类原因：

1. **`c_variadic` 特性未启用/不再被该配置接受（编译失败）**
- `tests/pass/c-variadic.rs`
- `tests/pass/both_borrows/c_variadics.rs (revision stack/tree/tree_implicit_writes)`
- 典型报错：`error[E0658]: C-variadic functions are unstable`、`use of unstable library feature c_variadic`。
- 本质是：测试代码依赖 `c_variadic`，但当前工具链/编译参数下没有启用该 unstable feature。

2. **标准库/API 变动导致编译失败**
- `tests/pass/intrinsics/portable-simd-ptrs.rs`
- 典型报错：`error[E0425]: cannot find function with_exposed_provenance in module std::simd::ptr`。
- 本质是：测试使用的 API 在当前 nightly 上不存在或路径变更。

3. **测试本身运行时 panic（不是编译期）**
- `tests/pass/adjacent-allocs.rs`：`never saw adjacent stack variables?`
- `tests/pass/address-reuse.rs`：`assertion failed: addrs.len() > 1 && addrs.len() < count`
- `tests/pass/intptrcast.rs`：`attempt to multiply with overflow`
- `tests/pass/ptr_offset.rs`：`attempt to multiply with overflow`
- `tests/pass/shims/socket-address.rs`：`assertion failed: addr_count == 2`
- 这类都表现为退出码 `101`，属于运行期断言/算术溢出失败。

4. **并发/线程模型相关：主线程提前结束或地址空间耗尽**
- `tests/pass/getpid.rs (revision with_isolation)`
- `tests/pass/getpid.rs (revision without_isolation)`
- 报错：`the main thread terminated without waiting for all remaining threads`
- `tests/pass/0weak_memory/consistency_sc.rs`
- `tests/pass/concurrency/address_reuse_happens_before.rs`
- 报错：`resource exhaustion: there are no more free addresses in the address space`
- 本质是并发测试在当前 Miri 地址分配/线程调度下触发资源或生命周期约束。

5. **外部符号处理语义变化（编译期被拒）**
- `tests/pass/weak-linkage-missing.rs`
- 报错：`unsupported operation: can't use unknown foreign function symbol test_symbol_that_does_not_exist`
- 说明当前行为不再把该 missing weak symbol 当作可接受路径（例如 `is_none()`），而是直接报 unsupported。

6. **期望输出文件（.stdout/.stderr）与实际输出不一致**
- `tests/pass/debugger_test.rs`：实际输出了 `before add` / `result: 15`，但用例原本“期望无输出”。
- `tests/pass/heap_alloc.rs`：出现了 `integer-to-pointer cast` warning + 大量调试输出 + stdout 文本，和预期不匹配。
- `tests/pass/stacked_borrows/stack-printing.rs`：栈打印格式明显变了（旧格式 `SharedReadWrite<TAG>`，新格式 `stack.len=...`）。
- 这类通常是“行为/输出格式变了，测试基线未更新”（`--bless` 可更新基线，但要先确认变更是预期的）。

7. **Miri/rustc ICE（解释器或编译器内部错误）**
- `tests/pass/zst.rs`：`src/alloc_addresses/mod.rs` 中 `Option::unwrap()` on `None`
- `tests/pass/intrinsics/intrinsics.rs`：同类 `Option::unwrap()` on `None`
- `tests/pass/function_calls/abi_compat.rs`：`src/machine.rs` 栈地址一致性检查 panic（`current stack address ... must equal ...`）
- `tests/pass/function_calls/tail_call.rs`：同类栈地址一致性 panic
- `tests/pass/tree_borrows/spurious_read.rs`：同类栈地址一致性 panic
- `tests/pass/issues/issue-154385-no-mangle-generic.rs`：rustc internal compiler error（`Instance::mono ... has type parameters`）
- 这组不是普通用例失败，而是 Miri/编译器 bug 级别问题。
