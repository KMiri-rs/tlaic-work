# BlueOS: `INoLock::this_mut` is an unsound API that breaks aliasing rules

## Body

https://github.com/KMiri-rs/KMiri/issues/227 finds the API violates alising rules, and https://github.com/KMiri-rs/vivoblueos-kernel/pull/14 workarounds the problem by not using `.lock()` which boils down to `this_mut`.

https://github.com/KMiri-rs/KMiri/issues/227#issuecomment-6097475139 minimized the code as per how the kernel uses the API. 

But the code can be further slimmed to a local lock write as follows

```rust
// NOTE: this is an example to show `lock.write()` still violates alising rules,
// and thus it's not a sound API at all.
#[test]
fn test_inlock_from_local_storage() {
    let slot = ThreadLike { _id: 0, lock: INoLock::new() };
    unsafe { slot.lock.write() };
}
```
