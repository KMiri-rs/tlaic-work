# KMiri should reject unknown symbols and provide shims to keep them if desired

## Body

> KMiri doesn't soundly handle `extern fn` or external symbol addresses:
> 
> ```
> __einit_array=0xffffffff80014fad __sinit_array=0xffffffff80014fcf
> An uncaught panic occurred: panicked at /home/zjp/KMiri/asterinas/ostd/src/lib.rs:189:20:
> attempt to subtract with overflow
> ```
> 
> Symbols `__sinit_array` and `__einit_array` are generated by linker, so kmiri should ideally reject unknown  symbols.
> 
> But currently kmiri allocates the symbols even if they don't exist. Miri doesn't have the problem, because such code won't link after  compilation. [playground](https://play.rust-lang.org/?version=stable&mode=debug&edition=2024&gist=3d8b281041152abaf613a9005dcbfe8a)
