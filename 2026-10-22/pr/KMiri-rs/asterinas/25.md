## Body

Fix https://github.com/KMiri-rs/KMiri/issues/102

The problem is that concrete pointer provenance is inherited even though the heap allocation is freed. 

Miri's provenance is defined as follows:

```rust
pub enum Provenance {
    Concrete { alloc_id: AllocId, tag: BorTag },
    Wildcard,
}
```

That's to say for `Pointer<Option<Provenance>>` 
*  `Pointer<None>` is almost a temporary state or as a part of signature for provenance-agnostic case
* `Pointer<Provenance::Concrete { alloc_id, tag }>` is a pointer which is derived from an accurate AllocId and idenditifed with strict access check to the borrow stack
* `Pointer<Provenance::Wildcard>` is a pointer whose provenance is exposed, it may point to any (known or unknown) allocation, and access check to the borrow stack is lenient (a separate check path via exposed_tags set)

For the case in https://github.com/KMiri-rs/KMiri/issues/102 ,  the heap slot  has  boxed allocations (as backing BTreeMap node data) and trailing paddings (the range being `104..128`). Paddings' borrow  stack don't contain the accessing bortag which derives from the unique box bortag. Solutions in deallocation or alloc call 
* expose the provenance during deallocation, when the pointer access heap slot with a bortag, the sb check can pass because exposed_tags contains the bortag
* refresh the borrow stack during deallocation, all the slot range is reset with the same unique bortag, and concrete tag is successfully checked because the stack is overridden
* refill the slot with zeros to refresh provenance
