## Body

fix https://github.com/KMiri-rs/KMiri/issues/54


This commit updates `ostd/src/arch/miri/mm/mod.rs` to remove direct architecture-specific operations (especially ones that rely on x86 register/assembly paths) in the Miri build path.

Main changes:
- All TLB flush helpers are turned into no-ops in Miri:
  - `tlb_flush_addr`
  - `tlb_flush_addr_range`
  - `tlb_flush_all_excluding_global`
  - `tlb_flush_all_including_global`
- Page-table switching no longer writes to `CR3` directly.
  - `activate_page_table` now calls an external Miri hook: `kern_miri_set_root_page_table(root_paddr)`.
  - The `root_pt_cache` parameter is now ignored (`_root_pt_cache`).
- Current page-table lookup no longer reads `CR3` directly.
  - `current_page_table_paddr` now calls `kern_miri_get_root_page_table()`.
- Adds two `unsafe extern "Rust"` declarations for these Miri runtime hooks, with comments describing their expected behavior.

Net effect:
- The Miri memory-management path is simplified and decoupled from low-level x86 register manipulation/asm-related logic.
