## Summary

Run the Rust kernel doctests under Miri, getting 261 of 352 (74%) to pass and thus catch UB locally.

cc https://github.com/orgs/KMiri-rs/discussions/271#discussioncomment-18927013

## Background

Upstream `rust/kernel` doctests run through KUnit (`CONFIG_RUST_KERNEL_DOCTESTS=y`) rather than plain `rustdoc --test`. Under Miri they fail with "can't call foreign function" because the examples depend on `rust_helper_*` extern functions. This PR fills those gaps with a Miri-specific generated test file plus pure-Rust shims.

## Changes

- **`scripts/rustdoc_test_gen_miri.rs`**: new generator that reassembles the raw test bodies from `rust/test/doctests/kernel/` into `rust/doctests_kernel_generated_miri.rs`, wrapping each doctest in a `#[test]` fn.
  - Shims `rust_helper_krealloc_node_align`/`vrealloc`/`kvrealloc` in terms of `realloc`/`free`.
  - Shims `rust_helper_REFCOUNT_INIT`/`refcount_inc`/`refcount_dec`/`refcount_dec_and_test` in pure Rust.
  - Provides a dummy `LocalModule` implementing `ModuleMetadata` with a null `THIS_MODULE`.
- **`rust/Makefile`, `Makefile`, `scripts/Makefile`**: wire into kbuild — new `miri-kernel-doctest` → `rusttest-kernel-doctest-miri` with `--cfg miri` and `--extern` pointing at the rlibs under `rust/test/`.
- **`makefile.local`**:
  - `KIND=unit|doctest|all` target selection, plus `miri-unit` / `miri-doctest` aliases.
  - `miri-doctest-fast`: skips full kbuild and runs the generated file directly against `$(MIRI_BIN)` for fast iteration.
  - `MIRI_DOCTEST_SKIP`: explicitly skips ~91 tests Miri can't handle yet (maple_tree, rbtree, atomic, hrtimer, …).
  - `MIRI_FLAGS`: adds `-Zcrate-attr='feature(arbitrary_self_types)'` (among others).
- Minor fixes: derive `Debug` for `AllocErrorKind` and the sample `State`; add `use std::dbg;` in the generated file.

<details><summary>Explain</summary>
<p>

**原始 doctest 运行流程（Rust for Linux）**

1. 顶层入口先进入 `rust` 子构建  
   - `rusttest` 目标在顶层 Makefile 定义：  
     [Makefile:2030-2032](https://github.com/KMiri-rs/linux/blob/1a86c8d19dbc194298bec82102f3f3b19464eada/Makefile#L2030-L2032)

2. `rust/Makefile` 里通过 `rustdoc --test --no-run` 抽取 doctest  
   - 关键命令在 `cmd_rustdoc_test_kernel`：  
     [rust/Makefile:394-410](https://github.com/KMiri-rs/linux/blob/1a86c8d19dbc194298bec82102f3f3b19464eada/rust/Makefile#L394-L410)  
   - 这里会调用 `--test-builder .../scripts/rustdoc_test_builder`，然后再跑 `scripts/rustdoc_test_gen`。

3. 生成物是 KUnit 包装，而不是普通 Rust `#[test]`  
   - 规则输出 `doctests_kernel_generated.rs` 与 `doctests_kernel_generated_kunit.c`：  
     [rust/Makefile:412-416](https://github.com/KMiri-rs/linux/blob/1a86c8d19dbc194298bec82102f3f3b19464eada/rust/Makefile#L412-L416)  
   - 生成器把 doctest body 封成 KUnit case（`rust_doctest_kernel_*`）：  
     [scripts/rustdoc_test_gen.rs:155-229](https://github.com/KMiri-rs/linux/blob/1a86c8d19dbc194298bec82102f3f3b19464eada/scripts/rustdoc_test_gen.rs#L155-L229)

---

**在 Miri 上跑 doctest 的思路**

核心是“复用抽取阶段，替换最后一公里”：

- 复用 `rustdoc --test --no-run + test-builder` 这段抽取逻辑（它已经能把 doctest body 拆出来）。
- 不再生成 KUnit 包装，而是生成一个 **Miri 可执行的测试 crate**（每个 doctest 变 `#[test] fn`）。
- 复用已有 Miri 执行通道（`cmd_rustc_miri_test`）来跑这个 crate：  
  [rust/Makefile:437-449](https://github.com/KMiri-rs/linux/blob/1a86c8d19dbc194298bec82102f3f3b19464eada/rust/Makefile#L437-L449)

---

**我们做的修改（你当前分支）**

1. 新增一条 doctest→Miri 的并行流水线（不破坏原 KUnit 流水线）  
   - 在 `rust/Makefile` 增加 `miri-kernel-doctest` / `rusttest-kernel-doctest-miri` 目标，沿用 Miri 编译执行逻辑。
   - 目标依赖补齐了 `ffi/build_error/macros/pin_init/bindings/uapi/zerocopy/...` extern，避免 doctest 编译缺符号。

2. 新增 Miri 版 doctest 生成器（当前分支新增文件）  
   - 作用：把 `rust/test/doctests/kernel/*` 组装成 `doctests_kernel_generated_miri.rs`。
   - 另外加了 `MIRI_DOCTEST_FILTER`，可只生成某个源文件的 doctest（比如 `list_rs`）。

3. 为 Miri 补最小 helper shim（在生成的 crate 内）  
   - 解决 Miri 对内核 C helper foreign symbol 的限制（如 `krealloc_*`、`REFCOUNT_INIT`、`refcount_*`），让 `list` doctest 能真正跑起来。

// Use a cursor to remove the first element with the given value.
fn remove_first(list: &mut List<ListItem>, value: u32) -> Option<ListArc<ListItem>> {
    let mut cursor = list.cursor_front();
    while let Some(next) = cursor.peek_next() {
        if next.value == value {
            return Some(next.remove());
        }
        cursor.move_next();
    }
    None
}

// Use a cursor to remove the last element with the given value.
fn remove_last(list: &mut List<ListItem>, value: u32) -> Option<ListArc<ListItem>> {
    let mut cursor = list.cursor_back();
    while let Some(prev) = cursor.peek_prev() {
        if prev.value == value {
            return Some(prev.remove());
        }
        cursor.move_prev();
    }
    None
}

// Use a cursor to remove all elements with the given value. The removed elements are moved to
// a new list.
fn remove_all(list: &mut List<ListItem>, value: u32) -> List<ListItem> {
    let mut out = List::new();
    let mut cursor = list.cursor_front();
    while let Some(next) = cursor.peek_next() {
        if next.value == value {
            out.push_back(next.remove());
        } else {
            cursor.move_next();
        }
    }
    out
}

// Use a cursor to insert a value at a specific index. Returns an error if the index is out of
// bounds.
fn insert_at(list: &mut List<ListItem>, new: ListArc<ListItem>, idx: usize) -> Result {
    let mut cursor = list.cursor_front();
    for _ in 0..idx {
        if !cursor.move_next() {
            return Err(EINVAL);
        }
    }
    cursor.insert_next(new);
    Ok(())
}

// Merge two sorted lists into a single sorted list.
fn merge_sorted(list: &mut List<ListItem>, merge: List<ListItem>) {
    let mut cursor = list.cursor_front();
    for to_insert in merge {
        while let Some(next) = cursor.peek_next() {
            if to_insert.value < next.value {
                break;
            }
            cursor.move_next();
        }
        cursor.insert_prev(to_insert);
    }
}
