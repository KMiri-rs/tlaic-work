## Body

* Fix https://github.com/KMiri-rs/KMiri/issues/60
* Fix https://github.com/KMiri-rs/KMiri/issues/61

This PR handles the new stack allocations during stack popping:
1. Each thread now has a StackPopAllocTracker which is used to do stack allocation based on the saved SP in between before_stack_pop and after_stack_pop.
2. StackPopAllocTracker should be considered as isolated caller allocation data, especially with separated int_to_ptr_map; global_state int_to_ptr_map is for callee during the stack popping, so stack deallocation prefers removing the address from global_state.


Also
* Improves the debugger's stack pane by displaying the last_recorded_stack_ptr.
* Revert the physical memory layout in the config.

The maximum stack footprint is now only 6MB, a 70% reduction from the original 18.61MB in #15. No stack resource exhaustion. :tada:
